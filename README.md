# Million Items Board

Express-приложение с двумя списками для выбора, фильтрации и сортировки миллиона элементов. Frontend написан на JavaScript, HTML и CSS без сборщика.

## Запуск и проверки

Требуется Node.js 22 или новее.

```bash
npm ci
npm start
```

Открыть `http://localhost:3000`. Порт задаётся переменной `PORT`.

```bash
npm run dev    # перезапуск сервера при изменении исходников
npm run check  # проверка синтаксиса
npm test       # тесты API, очередей и хранения; около 13 секунд
```

Тест интервалов использует реальные production-таймеры: чтение раз в секунду, добавление раз в десять секунд. Остальные проверки охватывают конкурентные запросы, дедупликацию, порядок действий, границы страниц, фильтрацию и сортировку скрытых/видимых элементов.

## Поведение

- Изначально доступны ID `1`–`1000000`. Они представлены диапазоном, без массива миллиона объектов.
- Нажатие `+` выбирает элемент, `×` возвращает его в левый список.
- ID новых элементов — произвольные строки до 100 символов. Пробелы по краям удаляются, регистр учитывается. `01` и `1` — разные ID; пустые значения и управляющие символы запрещены.
- Поиск — совпадение подстроки ID, отдельно для каждой панели. Значения фильтров не сохраняются.
- API возвращает страницы по 20 элементов, последняя страница может быть короче. Дополнительные страницы загружаются при прокрутке. Каждая панель содержит максимум 20 строк DOM и хранит до шести страниц в клиентском кэше.
- Высота виртуальной прокрутки ограничена 8 млн пикселей с пересчётом диапазона: браузер может достичь последнего ID без превышения ограничения высоты DOM. Обычная прокрутка сохраняет шаг строк. `Home`/`End` переходят к началу/концу, `PageUp`/`PageDown` — на экран.
- Выбранные строки перемещаются за ручку `⋮⋮`, мышью или касанием. При перетаскивании у края контейнер прокручивается. Альтернатива: фокус на ручке и `Alt+↑`/`Alt+↓`.
- При фильтре переставляются только совпавшие элементы в их существующих позициях. Пример: `[11, 2, 12, 3, 13]`, фильтр `1`, перенос `13` перед `11` даёт `[13, 2, 11, 3, 12]`. Скрытые `2` и `3` остаются на своих местах. Перестановка применяется ко всем совпавшим выбранным ID, включая другие страницы.

## Очередь и серверное состояние

Состояние общее для всех клиентов, хранится в памяти одного Node-процесса. Обновление страницы сохраняет выбор и порядок; остановка/перезапуск процесса сбрасывает их и добавленные ID. Поэтому приложение запускается в одном экземпляре без cluster/нескольких реплик.

Единый планировщик с шагом 1 секунда:

1. Каждые 10 секунд применяет накопленные добавления.
2. Применяет изменения выбора и порядка по FIFO. Противоположные действия не теряются: `выбрать → убрать → выбрать` выполняются именно в этой последовательности.
3. Выполняет накопленные чтения. Чтения списка, счётчиков и статуса операции проходят через ту же очередь. Все чтения одного батча наблюдают одну ревизию.

`POST`/`DELETE` немедленно возвращают `202` и `operationId`: это подтверждение постановки в очередь, а не применения. Статус проверяется через `/api/operations/:id`. Интервалы считаются от старта процесса, а не от каждого запроса. При перегрузке обработка может занять больше одного интервала.

Дедупликация и защита:

- Идентичные чтения в очереди используют общий Promise и одно вычисление.
- Новый ID резервируется в `Map` до применения. Повторные запросы на добавление получают тот же operation ID; уже существующий ID возвращает `409`. Проверка наличия и запись выполняются последовательно в одном процессе.
- Повторные выборы/снятия выбора объединяются по ID до противоположного действия. Последовательные одинаковые перемещения также объединяются. `Set` гарантирует уникальность выбранных ID.
- Заголовок `Idempotency-Key` позволяет повторить операцию, в том числе после её выполнения, с тем же результатом. Использование ключа для другого тела запроса возвращает `409`.
- Завершённые операции и ключи хранятся 5 минут. Очереди ограничены: 10 000 изменений/добавлений, 2000 уникальных чтений, 20 000 активных HTTP-запросов. Переполнение возвращает `503` с `Retry-After: 1`.
- Один батч обрабатывает до 500 изменений с ограничением времени выполнения, до 256 уникальных чтений и до восьми разных фильтров диапазона. Остальное остаётся в очереди. Между порциями изменений сервер уступает цикл событий для приёма запросов.
- Поиск по исходному диапазону выполняется в Worker Thread. Индексы фильтров кешируются в LRU на восемь запросов. Для глубокой страницы бинарный поиск находит её начало без прохода по всем предыдущим страницам.

Клиент отменяет устаревшие запросы при смене фильтра и не смешивает страницы разных ревизий. Ошибки отображаются в интерфейсе; загрузку можно повторить кнопкой.

## API

| Метод | Путь | Параметры / тело |
| --- | --- | --- |
| GET | `/api/items` | `side=available\|selected`, `q`, `offset`, `limit=20` |
| GET | `/api/state` | Счётчики и ревизия |
| POST | `/api/items` | `{ "id": "custom-A" }` |
| POST | `/api/selected` | `{ "id": "42" }` |
| DELETE | `/api/selected` | `{ "id": "42" }` |
| POST | `/api/selected/move` | `{ "id": "42", "targetId": "50", "position": "before", "query": "" }` |
| GET | `/api/operations/:id` | Статус `queued`, `applied` или `rejected` |
| GET | `/healthz` | Проверка доступности процесса без очереди |

Размер страницы всегда 20; другие значения `limit` отклоняются. Фильтр — строка до 100 символов, offset — неотрицательное безопасное целое число. Ошибки данных, существования ID и актуальности DnD проверяются также в момент применения операции. API-ответы имеют `Cache-Control: no-store`.

## Развёртывание

Сервер и статический frontend размещаются одним сервисом. Исходники готовы для Render (`render.yaml`) или Docker (`Dockerfile`).

Render:

1. Создать репозиторий GitHub и загрузить `src`, `public`, `test`, `package.json`, `package-lock.json` и конфигурационные файлы. `node_modules`, `.env` и `artifacts` исключены в `.gitignore`.
2. В Render выбрать **New → Blueprint**, подключить репозиторий и применить `render.yaml`. Альтернатива: **New → Web Service**, среда **Node**, build command `npm ci`, start command `npm start`, health check `/healthz`, один экземпляр.
3. После успешного развёртывания открыть выданный HTTPS-адрес и проверить обе панели. Ссылка на этот сервис и ссылка на репозиторий — результат для сдачи.

Бесплатный сервис может засыпать/перезапускаться; при новом запуске данные в памяти сбрасываются. Это соответствует хранению только на протяжении работы процесса.

Docker:

```bash
docker build -t million-items-board .
docker run --rm -p 3000:3000 million-items-board
```

```text

src/batcher.js        очереди, таймеры, дедупликация, статусы операций
src/store.js          серверное состояние, страницы, перестановки
src/filter-index.js   LRU и взаимодействие с потоком фильтрации
src/filter-worker.js  фильтрация исходного диапазона
src/server.js         запуск и завершение процесса
public/               интерфейс без сборщика
test/                 автоматические проверки
```
